# Development Goal And Project Direction

## Target Role

My goal is to grow from a frontend developer into a realtime/IoT systems designer who builds predictable and trustworthy control interfaces between users, data and physical devices.

I want to combine strong frontend execution with responsibility for architecture, system behavior, control UX, event modeling and reliability.

## Positioning

The role I want to aim for is:

> Realtime/IoT systems designer with strong frontend execution, specializing in control UI, telemetry, event-driven architecture and reliable control UX.

This means the project is not only an exercise in UI implementation. It should demonstrate the ability to design a system that reacts to realtime data, handles uncertainty and gives the user reliable control over device state.

## Core Assumption

AI should be an implementation tool, not the owner of the project.

Human responsibility remains on the side of:

- system architecture,
- event and state modeling,
- application behavior rules,
- control UX,
- failure handling,
- data interpretation,
- decision documentation.

AI can help with coding, organizing documentation, generating variants and speeding up work, but it should not replace deliberate system design.

## Skills This Project Should Develop

This project should focus most strongly on developing the following areas:

1. Designing system behavior.
2. Modeling events and states.
3. Realtime UX and control UI.
4. Handling failures and data uncertainty.
5. Telemetry and time-series data analysis.
6. Architectural decision documentation.
7. Using AI as an implementation tool, not as the system designer.

## Criteria For A Good Project Decision

A good decision in this project should help answer these questions:

- Does the system behave predictably?
- Does the user understand what is happening with the device?
- Does the UI show the difference between desired, confirmed and uncertain state?
- Are failures, delays and missing data handled explicitly?
- Can events and commands be traced?
- Has the decision been documented clearly enough to revisit later?

## What This Project Should Not Pretend To Be

This project should not be just another frontend application or a simple dashboard.

It is not only about:

- a polished interface,
- quickly connecting data,
- demonstrating a framework,
- generating a large amount of code with AI.

The goal is to design a small but realistic control system where event flows, device state, delays, confirmations, reliability and user trust in the interface all matter.

## Practical Definition Of Success

This project will be a good development step if, after completing it, I can clearly explain:

- how the full flow works from user action to device state change,
- which events and commands exist in the system,
- how the UI reacts to confirmed, pending, delayed and failed states,
- which architectural decisions were made and why,
- how the system behaves when a device fails, data is delayed or data is missing,
- where AI helped with implementation and where the decisions belonged to me.
